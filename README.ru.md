# DNSmarty

[English](README.md)

Self-hosted Smart DNS. Панель одна пишет в PostgreSQL и сама пушит конфиг агентам DNS и прокси. Клиентский трафик идёт только на агентов.

Один образ Go (`panel`, `dns`, `proxy`, `migrate`) и интерфейс на React. Чужих списков доменов нет: в сиде только `example.com`.

## Возможности

- Control plane и data plane разделены. Панель, DNS и прокси могут стоять на одной машине или на разных.
- Порт 53, DoT `:853` и DoH `:8443` используют один decision path.
- SNI-прокси склеивает TCP и не терминирует TLS. UDP и QUIC нет.
- Прокси несколько. Если панель не достучалась 30 секунд, IP выпадает из ротации.
- Клиент не из allowlist получает `REFUSED`. Пустой список отказывает всем, кроме bootstrap-CIDR.
- Ключ узла показывается один раз и в базе лежит только шифротекстом.

## Требования

- Linux для DNS и прокси (`network_mode: host`, иначе allowlist увидит адрес моста)
- Docker и Compose v2
- Образ `ghcr.io/jav1x/dnsmarty` или локальная сборка

## Быстрый старт

```bash
bash <(curl -Ls https://raw.githubusercontent.com/Jav1x/DNSmarty/main/scripts/dnsmarty.sh) @ install
```

Скрипт берёт язык из локали системы, проверяет Docker, порты, файрвол и не установлена ли панель, затем пишет `.env` в `/opt/dnsmarty` и один раз показывает пароль администратора. Панель: `https://127.0.0.1:7443` (внутренний сертификат Caddy, браузер предупредит). Команда `dnsmarty` открывает меню.

| Команда | Что делает |
| --- | --- |
| `install` | Проверить машину, создать `.env`, скачать образы, поднять Postgres, миграции, панель и Caddy |
| `update` | Скачать образы и пересоздать контейнеры |
| `up` / `down` / `restart` / `status` / `logs` | Управление compose |
| `edit-env` | Править `/opt/dnsmarty/.env` |
| `uninstall` | Остановить контейнеры и оставить `/opt/dnsmarty` |
| `install-script` | Поставить только команду `dnsmarty` |

## Агенты

В панели: Узлы → выпустить ключ. Публичный IP задаётся явно, из интерфейса контейнера он не берётся. Адрес и порт — куда панель будет звонить.

На машине агента:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/Jav1x/DNSmarty/main/scripts/dnsmarty-node.sh) @ install
```

Без меню:

```bash
dnsmarty-node install --role dns --key КЛЮЧ --port 9443
dnsmarty-node install --role proxy --key КЛЮЧ --port 9444
```

`sh install-node.sh dns` делает то же самое и спрашивает ключ и порт. В панели нажмите «Далее». Закрытый порт или чужой ключ остаётся ошибкой на карточке. Успешная проверка сразу отправляет снимок.

DNS слушает 53, 853 и DoH 8443. Прокси слушает 80 и 443. Порт управления отдельный. На одной машине это два контейнера.

Файлы лежат в `/opt/dnsmarty-dns` или `/opt/dnsmarty-proxy`. `dnsmarty-node update` скачивает образ и пересоздаёт контейнер.

## Клиенты и имена

Добавьте CIDR, с которого будете проверять. Пустой список отказывает всем, кроме bootstrap-CIDR.

Укажите upstream, например `1.1.1.1:53`. И DNS, и прокси спрашивают его напрямую, не через свой порт 53.

`example.com` уже есть как суффикс. Привяжите прокси и вес. По кругу и по весу отдаётся один или два A. Липкий `/24` отдаёт один.

С разрешённого адреса:

```bash
dig @ПУБЛИЧНЫЙ_IPV4_DNS www.example.com A
```

A — публичный адрес живого прокси, TTL по умолчанию 30. Неизвестное имя уходит на upstream. Остальные клиенты получают `REFUSED` на 53, DoT и DoH.

Если панель не видит прокси 30 секунд, его IP пропадает из следующего снимка. Имя при этом на upstream не уходит. Если недоступна панель, агент держит последний снимок.

## Разработка из этого дерева

```bash
cp .env.example .env
# замените каждый change-me

docker compose --profile panel up -d --build
```

Интерфейс в `web/`. `npm run dev` ходит в API на `127.0.0.1:8080`. Сборка образа сама запускает `npm run build`. Не коммитьте `web/node_modules` и `internal/panel/dist/assets`.

```bash
go test ./...
```

Для тестов на Postgres нужен Docker.

## Секреты

Секреты только в `.env` или Docker secrets. В образ они не копируются. В `.env.example` только заглушки. Ключ узла в Postgres — шифротекст AES-GCM от `PANEL_MASTER_KEY`. Не публикуйте `.env`, приватные ключи и `certs/*.pem`.
